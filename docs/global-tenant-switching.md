# 全局租户切换

系统管理员登录后，通过顶栏选择操作租户。业务页面未选择租户时显示提示；业务 HTTP 请求未携带有效选择时由后端统一拒绝。租户管理、全局菜单、登录资料和改密保持平台范围。业务页面不再重复显示租户筛选，门店筛选保留。

选择按当前标签页保存，跨页面保持，刷新或退出账号后重新选择，避免不同标签页互相改变范围。切换前提示未保存内容会被清空，确认后重建页面，重置分页、门店、详情、表单和收银草稿，取消旧租户请求并拒绝过期响应回填。积分能力同时刷新。租户开通或状态变更后可通过顶栏刷新按钮重新加载可用租户。

## 工程边界

- wj-framework 只新增通用 TenantContext 临时作用域；SQL 租户拦截、自动填充和字典翻译使用操作租户。没有显式作用域时保留原行为。作用域关闭后恢复外层租户，JWT 请求结束额外清理。
- hair-salon 的 SalonTenantInterceptor 解析 X-Tenant-Id，只允许 ROOT 切换，并通过 SysTenantService 校验目标存在、启用且未到期。普通用户固定使用 JWT 登录租户，伪造其他租户标识会被拒绝。
- 平台接口路径、租户主表、业务角色和可用性判断均在业务工程；框架不包含这些策略。TenantContextRunner 复用通用作用域用于开通、支付回调和定时任务，不再修改登录身份。

## 数据一致性

SecurityUtils.getTenantId() 表示当前操作租户，UserContext.getTenantId() 保留登录身份所属租户。新增记录自动填入操作租户，实际操作人 ID 和权限不变。既有租户查询参数不能扩大 TenantLine 范围；财务 Mapper 显式绕过拦截，因此 Service 强制覆盖客户端租户参数。字典管理按操作租户查询和维护，下拉及翻译继续使用通用模板叠加当前租户覆盖。

用户和角色的关联表没有租户列，业务在操作关联前校验主记录归属；字典修改与删除校验所属租户。全局用户/部门缓存仍按全局唯一 ID 保存，通过内部专用 Mapper 批量重建所有租户数据，避免选中租户时清空其他租户缓存。支付配置等现有按租户的缓存继续使用操作租户。

该变更不新增表或权限串，无需数据库迁移。部署须同时更新框架依赖和应用后端，再发布前端；外部管理员 API 调用需为业务请求增加 X-Tenant-Id。普通租户调用不需要增加请求头。

## 验证

TenantScopeTest 覆盖管理员切换、普通用户越权标识、无选择与非法租户、禁用/过期租户、平台范围、作用域嵌套及异常恢复、SQL 读写隔离、新增租户与审计操作人、财务查询参数覆盖、全局缓存重建。框架 DictAspectTest 验证 ROOT 显式作用域使用租户字典覆盖。
