## 6. 跨阶段公共事项

每个阶段落地时需同步处理，避免遗漏：

| 事项 | 说明 |
|------|------|
| **租户隔离** | 业务表继承 `BaseTenantEntity`，查询/导出/报表强制带租户条件（需求 6.4、27.2） |
| **门店数据权限** | 走 `salon_store_user` + `SalonStorePermissionService`，复用现有机制 |
| **权限种子** | 新接口同步 `perm`（`biz:xxx:动作`）种子；`sql.init.mode=never`，存量库手工跑 SQL |
| **`@PreAuthorize`** | 每个对外 HTTP 方法必备；仅登录 `isAuthenticated()`，按钮级走 perm |
| **模型字段说明** | Entity 字段 `/** */` Javadoc；Form/Query/VO 字段 `@Schema`；含义与 SQL COMMENT 一致 |
| **建表注释** | PG 用 `COMMENT ON TABLE/COLUMN`；schema.sql 带注释，存量库用 `sql/migrate-*.sql` |
| **字典** | 业务只存 value；VO `@Dict` + Controller `@QueryDict`，勿手写拼装 |
| **编号规则** | 业务单号统一走 P10 编号规则服务，勿散落各处硬编码 |
| **可追溯** | 订单/支付/退款/充值/余额变动/卡项核销/提成/日结 必须可追溯（需求 24.4） |
| **防重复提交** | 收银、充值、退款等写接口按需 `@PreventDuplicateResubmit`（需求 24.2） |

## 7. 推进建议

1. **先收口现有能力**：权限错误/空态、会员抽屉布局、手机导航、退款积分一致性；进度不能只看接口和页面是否存在。
2. **前置积分开关**：按店铺简化会员和收银体验，同时保留历史退款和流水；不把关闭开关当作修复退款积分问题的替代。
3. **优先推进 P6 收口 → P8 对账/日结 → P9 经营工作台**；P7 提成按业务需要后置，P3 核销暂缓。
4. **前端升级按独立清单推进**：动态登录、经营工作台、高效收银为首批代表性页面，见 [优化文档](frontend-product-ui-review-2026-11-12.md)。真实经营指标需先定义口径与聚合接口。
5. **P11 品牌配置可穿插**，按配置实现店名/Logo 等差异；不改变租户隔离与核心交易规则。
