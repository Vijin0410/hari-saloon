# Hair Salon UI Evolution Guide

> 基于 `frontend-design` 设计理念，对现有系统 UI 产品质量的分析与演进方向。
> 原则：**不推翻已有优秀页面**，以会员模块为标杆，逐步将「普通后台 CRUD」提升为「专业美业 SaaS 产品」。
> 最后更新：2026-08-11

---

## 0. 背景与定位

### 0.1 产品定位

Hair Salon 是面向独立理发店 / 美发店 / 造型工作室的 **美业 SaaS 管理平台**（首期单店商户为主）。核心业务闭环：**会员 → 充值 → 收银 → 退款 → 日结**。

目标用户：商户老板、店长、收银员、发型师、财务。他们信息化水平不一，要的是「打开就能用、能快速理解经营状态、能快速完成工作」的工具，而不是「看懂字段才能用」的后台。

### 0.2 当前完成度

| 阶段 | 模块 | 状态 | 前端 UI 现状 |
|------|------|------|--------------|
| P0 | 系统管理底座（用户/角色/菜单/部门/字典/租户/门店） | ✅ | 风格分化，部分模板感重 |
| P1 | 会员资产闭环（等级/余额/积分/流水/标签/备注） | ✅ | **已优化为标杆** |
| P2 | 服务项目与商品主数据 | 🔄 | 接口字段直出，模板感重 |
| P4-P8 | 充值/收银/退款/财务日结 | ⬜ | 未建 |
| P9 | 报表与看板 | ⬜ | 工作台当前为系统底座视角，需重构 |
| P10-P11 | 系统设置/品牌客制化 | ⬜ | 未建 |

### 0.3 演进原则

1. **不推翻已有优秀页面** -- 会员模块是标杆，作为视觉 / 交互 / 信息展示参考，不重设计。
2. **业务驱动，不是字段驱动** -- 页面服务谁、最高频操作是什么、什么信息最重要，先回答这些再选 UI 形态。
3. **不强制卡片化** -- 流水 / 日志 / 配置类数据保留专业表格；会员 / 商品 / 服务等业务实体优先业务化展示。
4. **保持工程稳定** -- 技术栈、架构、组件体系、接口、权限不变，只动 UI 层。
5. **逐步演进** -- 先修规范洼地（Tenant/Store/服务商品），再统一基础（表格/分页/状态色/字体），最后建新模块（工作台/收银/财务）。

## 1. 当前优秀页面分析（会员模块标杆）

`MemberPage.tsx` 已完成优化，是当前系统的 UI 设计基准。以下提炼其可复用模式。

### 1.1 页面结构

```
页头（标题 + 副标题 + 主操作）
  ↓
查询卡片（搜索框 clearable + 租户/门店/等级/标签筛选 + 查询按钮）
  ↓
列表（专业表格）—— 流水型数据合理保留表格
  ↓
分页
  ↓
详情（Modal + Card 分区）—— 业务实体用档案化展示
  ↓
数量调整弹窗（余额/积分）—— 方向 Tab + 实时预览
```

**关键判断**：列表用表格、详情用卡片。会员既是「可枚举的列表数据」又是「有档案的业务实体」，两种形态并存，按场景切换。

### 1.2 可复用设计模式

#### 模式 A：档案头部（Profile Header）

圆形头像（无图取姓名首字，紫底白字 `bg-salon-accent`）+ 姓名（`text-lg font-semibold`）+ 等级 / 状态 `Badge` + 手机（灰 `text-sm`）。

```
[ 紫 ]  张三  [黄金会员] [正常]
 圆      138****1234
```

适用：会员、用户、租户、门店、员工等「人 / 主体」类实体的详情头部。

#### 模式 B：核心资产卡（Asset Stat Card）

`text-[28px] font-bold` 大号数字 **独占行**，操作按钮放标题行右上角（主操作 `primary` / 次操作 `secondary`）。

```
账户余额                    [调整余额] [余额流水]
¥ 1,234.00
可用余额
─────────────────────
最近充值    最近消费
2026-08-01  2026-08-10
```

**禁止**：长金额与按钮并排（会重叠）。

适用：余额、积分、营业额、充值总额等「老板最关心的核心数字」。

#### 模式 C：四宫格明细（Stat Grid）

`grid grid-cols-4 gap-3`，每格 `rounded-md bg-stone-50 p-3`，标题灰小字 + 值深色。

```
本金余额      赠送余额      冻结金额      可用余额
¥1,000.00    ¥200.00      ¥0.00        ¥1,200.00
```

适用：一个主体的多个并列数值明细（余额分桶、支付方式汇总、日结各收入项）。

#### 模式 D：标签流 + 偏好两列

标签用 `Badge tone="info"` 流式排列；偏好用 `grid grid-cols-2` 的 `label / value` 子卡片，标题灰小字 + 值深色。

适用：会员标签、会员偏好（发质 / 偏好发型 / 常用发型师 / 过敏 / 禁忌）。

#### 模式 E：数量调整弹窗（Adjust Dialog）

- 方向 Tab 单选（选中紫底白字，不动态改字段名）
- 统一「调整数量」+ 右侧 suffix 带符号实时预览（扣除兼容负号，`Math.abs` 后按方向取负）
- 「调整后」预览卡（不足显红 `text-rose-600`）
- 「调整原因」必填
- 按钮文案随方向（`确认增加` / `确认扣除`）
- 数量输入 `type="text"` + `inputMode="numeric|decimal"` + 正则承载中间态

适用：余额调整、积分调整、未来库存调整、手工业绩调整等所有「带方向的数值变更」。

#### 模式 F：流水专业表格

余额 / 积分流水用 `text-xs` 紧凑表格，变动额按正负绿 / 红着色，列含时间 / 类型 / 变动额 / 变动后 / 操作人。

适用：余额流水、积分流水、订单流水、退款记录、充值记录等所有「时间序列 + 金额变动」数据。**这类数据不要卡片化**。

### 1.3 当前 UI 优点（应对齐保持）

1. **设计 token 统一**：`salon-accent`(紫 #7c6aef) / `salon-ink` / `salon-line` / `salon-paper` / `salon-warm`(粉)，Tailwind v4 `@theme`。
2. **暗色模式全覆盖**：每处都带 `dark:` 变体，zinc 色阶。
3. **自建组件体系**：Card / Button / Badge / Input(clearable) / Select / Modal / EmptyState / Field，无第三方 UI 库，符合「不引依赖」约束。
4. **权限按钮化**：每个操作按钮 `hasPermission` 守卫，perm 串与后端 `sys_menu.perm` 对齐。
5. **状态 Badge 一致**：`success`/`danger` + 中文标签，全模块统一。
6. **空状态有引导**：`EmptyState` 带 title + description，非空数据 / 空列表都有处理。

## 2. 页面通用优化原则

### 2.1 页面结构统一

**当前问题**：两套页头并存（User/Role/Menu/Dept/Dict 用卡片式页头；Tenant/Store/Member/服务商品用裸标题）；两套表格样式并存（`border-t + uppercase tracking-wide` vs `divide-y + 普通表头`）。

**原则**：

| 元素 | 统一标准 |
|------|----------|
| 页头 | `<div className="flex flex-wrap items-center justify-between gap-3">`，左标题 `text-xl font-semibold` + 副标题 `text-sm text-zinc-500`，右主操作按钮 |
| 查询区 | 独立 `Card`（`rounded-lg border bg-white p-4`），搜索框必带 `clearable` |
| 表格 | 统一 `divide-y divide-salon-line` + `thead bg-slate-50` + `th px-4 py-3 text-left font-medium`，表头中文不 `uppercase` |
| 分页 | 统一带页码 + 总数 + 上一页/下一页（需补 `Pagination` 组件） |
| 详情 | 业务实体用 Modal + Card 分区；内容多时用 Drawer（需补组件） |

### 2.2 信息层级

**原则**：

1. **老板最关心的数字最大**：营业额、余额、积分等核心数字 `text-[28px] font-bold` 独占行；次级数字 `text-lg`；明细 `text-xs`。
2. **字段：值 禁止平铺**：用子卡片（标题灰小字 + 值深色）或四宫格，不用 `姓名：张三` 这种平铺。
3. **操作按钮放标题行右上角**：主操作 `primary`，次操作 `secondary`，危险操作 `danger`。
4. **同一页面操作不超过 3 个**：超过用「更多」下拉（需补 `Dropdown`）。
5. **业务语义字段优先于技术字段**：服务项目要突出「参与折扣 / 计算提成 / 会员价优惠」，而不是把 `discountable` / `commissionable` 藏在表单里。

### 2.3 操作设计

**原则**：

1. **动作命名用动词，说清会发生什么**：「保存」「确认扣除」「打印小票」，不用「提交」「确定」。
2. **同一动作在流程中名字不变**：按钮「发布」→ toast「已发布」。
3. **危险操作二次确认**：删除 / 退款 / 余额调整用 `ConfirmDialog` 或原因必填。
4. **高频操作就近**：列表行的「详情 / 编辑」放行尾；详情内的「调整余额 / 流水」放卡片右上角。
5. **操作密度收敛**：列表行操作统一为「1-2 主操作 + 更多下拉」，Role 页 4 按钮最挤，需收敛。

### 2.4 空状态

**原则**（CLAUDE.md 第 10 条已强制）：

1. **禁止显示 `-`**：所有空值统一「暂无」「暂无记录」「暂无标签」。当前 Tenant（联系人）、Store（编码/电话）、ServiceItem（会员价/时长）、Goods（条码/成本价）显示 `-`，违规。
2. **空列表用 `EmptyState`**：title + description + 可选 action（如「新增会员」）。
3. **空字段在详情里用「暂无」**：不显示 `-` 或空白。
4. **空状态是行动邀请**：不只是占位，要告诉用户「下一步做什么」。

### 2.5 状态展示

**当前问题**：状态色体系缺失。Badge `success` 用 violet，但 MemberPage 状态「正常」用 emerald 手写覆盖；ConfirmDialog/ForbiddenPage 用 amber；NotFoundPage 用 zinc；`salon-warm`(粉) 声明了却未用于任何语义。

**原则**：

1. **补状态色 token**（`index.css` `@theme`）：
   ```css
   --color-success: #10b981;  /* emerald */
   --color-warning: #f59e0b;  /* amber */
   --color-danger:  #f43f5e;  /* rose */
   --color-info:    #0ea5e9;  /* sky */
   ```
2. **Badge tone 映射统一**：`success` → emerald（不再用 violet），`warning` → amber，`danger` → rose，`info` → sky，`neutral` → zinc。
3. **状态语义**：启用/正常 → success；停用/禁用 → danger 或 neutral；待确认/预警 → warning；信息标签 → info。
4. **业务状态用色**：订单待支付 warning、已支付 success、已退款 neutral、部分退款 info；库存低于阈值 warning / danger。

### 2.6 表单设计

**原则**（CLAUDE.md 第 8/9/11 条已强制，此处补充设计层）：

1. **必用 react-hook-form + zod**：当前 Tenant/Store/服务商品用裸 `setForm` 无校验，是规范洼地。
2. **数字字段禁止裸 `type="number"`**：用 `type="text"` + `inputMode="numeric|decimal"` + 正则承载中间态。当前 ServiceItem/Goods/MemberLevel 全用 `type="number"`，违规。
3. **时间字段必配选择器**：`type="date"` / `type="time"`，禁止裸 Input + placeholder。Store 营业时间用裸 Input placeholder「09:00」，违规。
4. **表单分组**：字段多时用 `FormSection`（需补组件）分组（基础信息 / 价格规则 / 状态），不全平铺 grid。
5. **可空字段空串转 null**：zod `refine` 或前端转换，与后端三态一致。
6. **校验消息简体中文，就近显示**：`Field error`，提交按钮 `loading={isSubmitting}`。

## 3. 不同业务模块优化方向

> 每个模块区分「当前优化方向」（已有页面可改）与「未来规划方向」（P4-P11 待建）。

### 3.1 工作台（HomePage）🔴 优先级最高

**当前问题**：内容是「系统管理底座」视角，统计 `userCount/roleCount/menuCount/permCount`，快捷入口只有用户/角色/菜单管理。对理发店老板毫无意义，与需求文档 20.1「老板看板」完全脱节。

**当前优化方向**（P9 报表看板前置，可先用现有/轻量接口搭骨架）：

- **顶部核心指标卡**（复用 Asset Stat Card 模式）：今日营业额、今日订单数、今日充值、今日新增会员。`text-[28px] font-bold` 独占行 + 同比/环比小字。
- **快捷操作区**：开单（P5）、会员充值（P4）、新增会员、收银台。按角色权限显隐（收银员看到「开单」，老板看到「经营概览」）。
- **待办提醒区**：今日预约（P9 后）、低库存商品（P2 已有 stockQuantity）、待审批退款（P6）、生日会员（营销 P11）。
- **经营趋势**：近 7 天营业额折线（P8/P9 后接数据）。

**未来规划方向**（P9）：
- 门店排行、员工业绩排行（需求 20.1）。
- 角色化看板：老板看经营、店长看门店、收银员看开单入口、发型师看个人业绩。
- 主题色随租户品牌（P11 客制化）。

**注意**：在 P4-P8 数据接口就绪前，工作台可先搭「骨架 + 占位 + 现有可取数据（会员数/商品数/今日新增）」，不要为了数据齐全而阻塞。但要明确标注「待 P8 数据」，避免又退回系统底座视角。

### 3.2 会员管理（已优化，微调）

**当前**：MemberPage 是标杆，结构良好。

**当前优化方向（微调）**：
- 流水表格变动额着色当前用内联 `style={{color: green/red}}`，改用 `text-emerald-600` / `text-rose-600` className，与状态色体系统一。
- 余额明细四宫格 `bg-stone-50`，与状态色 token 对齐考虑。
- MemberLevelPage / MemberTagPage **未复用标杆设计语言**，需重点改造（见下）。

**MemberLevelPage 改造**：
- 等级是「有序递进链」（普通→银→金→钻石），不应是扁平表格。改为**阶梯卡片列表**：序号 + 等级名 + 等级色 + 权益摘要（折扣/积分倍率/充值优惠）+ 升级阈值 + 状态。
- 「专属权益 JSON」裸 Input 改为结构化编辑器（或至少多字段表单）。
- 补 zod，数字字段改 `type="text"+inputMode`。

**MemberTagPage 改造**：
- 标签是「视觉对象」（有颜色、会展示在会员身上），列表项应带**标签预览**（按所选颜色渲染实际 Badge 外观）。
- 颜色选择从英文 Select 改为**色板 grid**（圆点 + 中文名）。

**未来规划方向**：
- 会员画像（消费趋势、偏好分析、流失风险评分）。
- 会员分层看板（高价值/沉睡/流失，需求 21.4）。

### 3.3 服务管理（ServiceItemPage / ServiceCategoryPage）🔴 模板感重

**当前问题**：
1. 接口字段直出：`PageVO` 字段 → 表格列 → Form 字段一一对应，无业务化重组。
2. **折扣/提成开关在列表完全不展示**：`discountable` / `commissionable` 只在表单里，老板在列表看不到哪些项目参与折扣/提成（这是收银和业绩的关键开关）。
3. 价格 `¥{standardPrice}` 无千分位无两位小数；`memberPrice` 空显 `-` 违规。
4. 表单裸 `setForm` 无 zod，数字字段 `type="number"` 违规。
5. 无详情视图。
6. 未为 P5 收银「快速选择」留余地。
7. ServiceCategoryPage 占独立菜单，与主数据割裂。

**当前优化方向**：
- **列表加业务语义列**：用图标或 Badge 表达「参与折扣 / 计算提成」（如 ✓ 折扣、✓ 提成，或两个小 Badge）。
- **价格列用 `formatCurrency` 统一格式化**（需补工具函数）：`¥1,234.00`；会员价与标准价对比，会员价低于标准价时绿色标注优惠。
- **分类筛选提到查询区**：按分类筛项目；分类管理作为弹窗或子页，不占独立菜单。
- **补 zod，数字字段改 `type="text"+inputMode`**。
- **空值改「暂无」**：会员价 / 时长为空显「暂无」或「-」改「无」。

**未来规划方向**（为 P5 收银预留）：
- **快速选择卡片视图**：按分类分组的卡片网格，点选加入订单（收银开单时的高频场景）。列表是「管理视图」，卡片是「挑选视图」，可切换。
- 服务时长用于预约排期（P 预约）。
- 服务人员绑定（主服务人员 + 助理，需求 11.3）。

### 3.4 商品管理（GoodsPage / GoodsCategoryPage）🔴 模板感重

**当前问题**：与服务管理同构，外加：
1. **库存无预警**：`stockQuantity` 裸数字，无低库存标记（需求 17.5 库存预警是后续，但商品表已有字段）。
2. **成本价对所有角色展示**：成本价是财务敏感字段，应受权限控制（需求 23.5 敏感数据权限）。
3. 销售价 / 成本价未体现毛利率（老板视角）。

**当前优化方向**：
- **库存列加预警色**：低于阈值（如 ≤5）红色 Badge「低库存」。
- **成本价权限控制**：无 `biz:goods:cost:view` 权限的角色隐藏成本价列（需求 23.5）。
- **价格格式化**：同服务管理，用 `formatCurrency`。
- **分类合并**：同服务管理，GoodsCategoryPage 合并到主数据页。
- 补 zod、数字字段、空值规范。

**未来规划方向**：
- 库存进销存（入库/出库/盘点，需求 17，后续扩展）。
- 商品销售排行（需求 20.3）。
- 收银快速选择卡片视图（同服务）。

### 3.5 系统管理模块（User/Role/Menu/Dict/Tenant/Store/Dept）

**模板感排序**（重→轻）：Tenant > Store > User > Role > Dept > Dict > Menu

**当前优化方向**：

| 页面 | 方向 |
|------|------|
| Tenant | 引入 zod；空值改「暂无」；开通 Modal 强化「分步」感（基础信息→门店→数据同步 Card 分区）；考虑租户详情卡（管理员/门店数/同步状态）；统一表格/页头样式 |
| Store | 营业时间改 `type="time"`；空值改「暂无」；补 zod；移除「营业时间文案」与开关时间的语义重叠；授权用户区加搜索；统一表格/页头 |

**财务模块前置债务**：`format.ts` 缺 `formatCurrency`，当前会员页用内联 `¥{...toFixed(2)}`，散落各处。P8 前必须补：
```ts
export function formatCurrency(value: number | string | null | undefined): string {
  const numeric = typeof value === 'number' ? value : Number(value);
  if (!Number.isFinite(numeric)) return '¥0.00';
  return `¥${numeric.toLocaleString('zh-CN', { minimumFractionDigits: 2, maximumFractionDigits: 2 })}`;
}
```

## 4. 后续页面开发规范

**不要**从接口字段直接生成页面。新增页面遵循：

```
业务目标分析  →  信息架构设计  →  UI 方案设计  →  代码实现
```

### 步骤 1：业务目标分析

先回答（写在新页面 PR 描述或注释里）：

1. **页面服务谁？**（老板 / 店长 / 收银员 / 发型师 / 财务）
2. **用户为什么用这个页面？**（核心任务一句话）
3. **最高频操作是什么？**（开单？查余额？看今日营业？）
4. **什么信息最重要？**（哪个数字 / 哪个状态用户最关心）
5. **什么展示方式最符合业务？**（表格？卡片？时间线？看板？）

### 步骤 2：信息架构设计

- 列出页面要传达的「信息单元」，按重要性排序。
- 决定每个信息单元的形态：核心数字（Stat Card）/ 明细网格（四宫格）/ 列表（表格）/ 时间序列（Timeline）/ 关系（Badge 群组）。
- 决定主操作 / 次操作 / 危险操作的层级与位置。

### 步骤 3：UI 方案设计

- **选页面类型**（见下表）。
- **复用标杆模式**（见第 1.2 节）：能用 Asset Stat Card / 四宫格 / 档案头部 / 流水表格的，直接套。
- **检查设计语言**：颜色用 token、状态色统一、字体层级、空状态、暗色模式。
- **检查组件缺口**：需要的组件是否已有？缺的先补组件再写页面（避免页面内手写重复结构）。

**页面类型选择矩阵**：

| 数据性质 | 适用页面类型 | 示例 |
|----------|--------------|------|
| 可枚举的业务实体（会员/商品/服务） | 列表表格 + 详情档案 | MemberPage |
| 流水 / 日志 / 记录 | 专业表格（紧凑） | 余额流水、订单流水、退款记录 |
| 配置类（菜单/部门/字典） | 树形表格 / master-detail | MenuPage、DictPage |
| 经营数据汇总 | Dashboard（Stat Card + 趋势） | 工作台、日结 |
| 时间序列（预约/排班） | Timeline 时间线 | 预约管理（未来） |
| 单据详情（订单/充值/退款） | 单据视图（头部 + 明细 + 流程） | P5/P6 收银退款 |
| 数值变更 | 方向 Tab + 预览弹窗 | 余额/积分调整 |

### 步骤 4：代码实现

- 遵循 CLAUDE.md 第 1-11 条硬规范（分层 / HTTP 入参出参 / 鉴权 / 表单校验 / 时间字段 / 详情风格）。
- 复用 `shared/ui` 组件，缺组件先补。
- 跑通暗色模式、空状态、权限按钮、加载态。
- 风格对齐周边存量代码（最小改动精神）。

### 反模式清单（禁止）

1. ❌ 接口字段直接当表格列，不做业务化重组。
2. ❌ 业务实体（会员/商品/服务）只有编辑弹窗，没有只读详情。
3. ❌ 核心数字与按钮并排（长金额会重叠）。
4. ❌ 字段：值 平铺（用子卡片）。
5. ❌ 空值显示 `-`（用「暂无」）。
6. ❌ 流水 / 日志硬卡片化（保留表格）。
7. ❌ 表单裸 `setForm` 无 zod。
8. ❌ 数字字段裸 `type="number"`。
9. ❌ 时间字段裸 Input + placeholder。
10. ❌ 状态色随手用 emerald/violet/amber 不统一（用状态色 token）。
11. ❌ 每个列表页手写 `<table>` + 手写分页（封装 Table / Pagination）。
12. ❌ 操作按钮超过 3 个不收敛。
