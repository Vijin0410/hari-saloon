# P8 财务日结与 P9 经营报表实施说明

更新日期：2026-11-13。当前交付为财务、日结和经营报表第一版；员工提成报表随 P7，渠道账单自动对账和库存/营销分析按后续阶段扩展。

## 页面与范围

- 财务与日结：`/biz/finance`，提供日期、租户和授权门店筛选，消费/充值/退款明细、本金核对、支付方式汇总、CSV 导出及历史日结。
- 经营报表：`/biz/reports`，提供按月、按年度或自定义日期查询；月度和自定义日期显示每日趋势，年度显示每月趋势，并提供门店汇总、服务/商品/会员消费排行及导出。排行显示前20项。
- 工作台：复用财务接口展示今日消费实收、充值本金、成功退款、本月消费净额和今日新增会员。
- 日期最多366天，采用北京时间自然日和左闭右开时间范围；未来日期不可查询。

## 金额与时间口径

| 指标 | 口径 |
|------|------|
| 消费实收 | 已支付、部分退款、已退款订单的原实收，按 `paid_time`；含会员余额，不含积分折算 |
| 成功退款 | 仅成功退款，按 `success_time`，跨日退款计入成功日；处理中和失败不计 |
| 消费净额 | 当期消费实收减当期成功资金退款，跨日退款可导致单日负数 |
| 充值本金 | 成功充值本金，按 `pay_time`；预收款，不计消费收入 |
| 充值赠送 | 与本金分列，不计外部收款 |
| 外部净收款 | 消费外部收款加充值本金减外部退款，不含余额/积分，未扣渠道手续费 |
| 本金期初/变动/期末 | 按会员归属门店的本金流水累计，含人工调整、消费、退款；历史初始资产须有对应流水 |
| 服务/商品排行 | 订单行折后金额，积分抵扣前、退款前；当前金额级退款无项目分摊，不能直接作为最终提成基数 |
| 会员消费排行 | 原订单消费实收，退款前口径 |

支付方式分别展示现金、微信、支付宝、银行卡、余额、其他和积分折算；积分属于权益，余额属于内部扣款，均不计外部资金。跨店交易的资金归交易门店，本金流水仍按会员归属门店，二者不可直接当作同一门店负债口径相减。

## 日结

只能确认已结束的营业日。门店与营业日期在数据库具有唯一约束，并发或重复提交只能生成一份快照。全部汇总在重复读事务内生成，保存操作人、确认时间和备注。

快照不因后续交易变化而重写。详情比较原快照与当前完整报表，提示补入/变更数据；原始快照仍可查看、导出。日结不封锁历史交易，也不等同于交班、现金盘点或渠道到账对账。

## 权限与迁移

接口统一位于 `/api/v1/finance`。报表/明细查询允许 `biz:report:list` 或 `biz:finance:list`；日结记录需 `biz:finance:list`，确认需 `biz:finance:settle`，明细导出需 `biz:finance:export`。ROOT 全权限，其他用户始终受服务端重算的租户及门店白名单约束。

执行 `sql/migrate-p8-p9-finance.sql` 创建快照表、日期索引、菜单和按钮权限，脚本可重复执行。本机开发 PostgreSQL 已迁移；其他环境因默认 `sql.init.mode=never` 需手动迁移。迁移后重新登录刷新 JWT 权限。默认授权 ROOT、租户管理员和店长，店员不默认开放。
