# 退款积分与积分功能开关方案

更新时间：2026-11-12。状态：本期实施完成，代码、迁移与自动回归已落地。

关联：[实施计划](hair-salon-implementation-plan.md)、[业务需求](hair-salon-saas-requirements.md)。卡项核销继续暂缓。

## 1. 已实施范围

- 退款分别处理资金退回、原抵扣积分退回、消费奖励回收，独立记账并关联原订单、退款单及原批次。
- 部分退款采用累计成功资金比例，最终全退补齐尾差；纯积分订单支持 0 元全单退积分。
- 原抵扣积分保留原有效期；原批次已到期时，退回批次到期日设为退款当天加 30 天，当天仍可使用。
- 原奖励仍可用的部分从原批次扣回；已经过期的部分免扣；已经使用的部分记录为待追回积分，不把可用积分扣为负数。
- 后续消费奖励优先抵扣待追回积分。存在待追回时禁止新增积分抵扣；售后退回的原抵扣积分独立入账。
- 积分开关按租户生效，同租户所有门店共用。存量租户迁移保持开启，新租户默认关闭。

## 2. 退款算法与事务

记原实收资金为 R，原抵扣积分为 P，原实际消费奖励为 G，累计成功资金退款（含本次）为 C。当 R > 0：

- 累计应退抵扣积分 = floor(P × C / R)。
- 累计应回收奖励 = floor(G × C / R)。
- 本次处理数 = 累计应处理数减去先前成功已处理数；奖励已处理包含实际扣回、过期免扣及新增待追回。
- 最后一笔全额退款补足尾差，累计不超过原抵扣和原奖励数量。G 从原奖励流水读取，不按当前会员等级重新计算。

例如应收 100 元，1000 积分抵 10 元，资金支付 90 元并获赠 90 分：退 45 元时返 500 分、回收 45 分；再退 45 元时处理剩余数量。资金全退为 90 元，不重复退积分折算的 10 元。

R = 0 且原抵扣积分大于 0 时，允许 0 元全单退积分，不生成虚假资金分摊行；本期不提供按项目行部分退积分。

发起退款仅保存预计权益并占用额度，成功确认后才记积分账。同一订单持有数据库行锁，同一时间仅允许一笔处理中退款；失败释放额度，重复确认由条件更新保护。原奖励、返还批次、积分汇总与待追回在同一事务内更新。

## 3. 开关与权限

入口：业务配置 → 会员设置。租户管理员可修改，店长默认只读，店员默认无设置权限。修改记录操作者、时间及前后值。

| 场景 | 开启 | 关闭 |
|---|---|---|
| 会员列表与档案 | 积分列、资产卡、调整入口正常显示 | 隐藏日常积分组件，保留授权历史查询及待追回信息 |
| 收银 | 可使用积分并按规则赠送 | 隐藏积分控件，拒绝新抵扣，新交易不赠送 |
| 会员等级 | 显示积分倍率 | 隐藏倍率，余额和折扣继续有效 |
| 人工积分调整 | 按权限操作 | 后端拒绝普通人工调整 |
| 历史订单退款 | 按原流水退回、回收 | 继续处理原交易积分权益 |
| 积分批次与流水 | 正常保留 | 不清零、不删除，原有效期继续执行 |
| 已开始的扫码支付 | 按出码快照确认 | 继续按出码时开关与倍率快照确认 |

前端登录后、窗口恢复焦点及每 30 秒刷新能力；保存设置后立即刷新。后端每次开始支付实时读取设置，不依赖前端显示状态。配置读取失败显示重试提示。关闭前设置页展示现存积分、待追回汇总和停用过渡说明。

`wj.salon.point-expire-enabled` 继续仅控制过期任务，不替代租户业务开关。充值/营销送分及兑换等尚未建设的场景仍不属于本期。

## 4. 接口与数据

| 接口 | 权限 | 用途 |
|---|---|---|
| GET /api/v1/member-settings/capabilities | 已登录 | 读取当前租户积分能力 |
| GET /api/v1/member-settings/detail | biz:memberSettings:list | 设置及存量资产汇总 |
| PUT /api/v1/member-settings/update | biz:memberSettings:edit | 更新开关并写审计 |
| GET /api/v1/orders/{id}/refund-preview?amount= | biz:order:refund | 预览资金退款及积分权益 |

新增 `sys_tenant.points_enabled`、`salon_member.point_debt`、原流水退款已处理数与债务变动字段、订单积分能力和倍率快照、退款回收明细，以及 `salon_member_settings_audit`。流水类型新增 10=退款奖励回收、11=奖励抵扣待追回；9 仍表示退款退回抵扣积分。

存量升级执行 `sql/migrate-refund-points-toggle.sql`，脚本支持重复执行；新建库的 schema/data 同步包含结构、菜单权限与字典。现有库默认 `sql.init.mode=never`，其他环境须显式执行迁移。历史成功退款不追补扣回旧奖励；旧版已返积分流水只做处理标记，无法关联批次的旧记录不猜造有效期。
